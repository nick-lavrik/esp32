# /www — кастомна статика веб-порталу

Цей каталог у LittleFS пристрою **порожній за задумом**. Сторінка порталу
живе не тут, а всередині прошивки; тут лежить лише цей файл.

Оновлюється разом із кодом: `docs/web_portal.md` — повний опис,
`assets/www/index.html` — джерело сторінки.

## Звідки береться сторінка

`WebPortal` складає статику з ланцюжка `CompositeStaticSource`, і перемагає
джерело з БІЛЬШИМ пріоритетом:

| Пріоритет | Джерело | Що це |
|---:|---|---|
| 100 | LittleFS `/www` | цей каталог — **кастомна** статика, якщо вона комусь потрібна |
| −100 | PROGMEM | вшита в прошивку gzip-копія `assets/www/index.html` — звичайний шлях |

Тобто на чистій платі портал працює одразу після `pio run -t upload`, без
`uploadfs`: сторінка вже у прошивці. `uploadfs` потрібен лише для вмісту
LittleFS — фонових зображень, профілів мережі в `/network` і ось цього
каталогу.

## Як підкласти свою сторінку

Покласти файл сюди — і він перекриє вшиту копію за тим самим шляхом:

```sh
cp my-index.html data/www/index.html
pio run -e <env> -t uploadfs       # переписує розділ LittleFS ЦІЛКОМ
```

Або просто залити файл через сам портал: вкладка **Files** → `/www` →
`New file`. Так швидше й без кабелю.

Прибрати кастомну сторінку — видалити файл (та ж вкладка Files, або
`uploadfs` без нього): портал одразу повернеться до вшитої копії. Саме тому
знести звідси вебку не страшно — пристрій лишається настроюваним.

> **Увага до `uploadfs`:** він стирає розділ LittleFS цілком і заливає все з
> `data/`. Усе, що залито через портал і не лежить у `data/`, зникне.
> Профілі WiFi це не зачіпає — вони в NVS, не в LittleFS.

## Маршрути порталу

Усе, що не `/api/*`, віддається як статика (`/` → `/index.html`).
API — коротко; повна таблиця з параметрами в `docs/web_portal.md`.

| Метод | Шлях | Дія |
|---|---|---|
| GET | `/api/status` | uptime, heap, чи ввімкнена авторизація, перелік розділів |
| GET | `/api/job?id=N` | результат задачі: `queued` / `running` / `done` / `expired` |
| POST | `/api/auth` | змінити логін і пароль порталу |
| GET | `/api/wifi/status`, `/api/wifi/connections` | стан мережі, збережені профілі |
| POST | `/api/wifi/connections`, `/connect`, `/scan`, `/hotspot`, `/reconnect` | керування мережею |
| DELETE | `/api/wifi/connections?id=N` | видалити профіль |
| GET | `/api/console/log?since=N` | рядки логу з номера N |
| GET | `/api/commands/list`, `/api/commands/shortcuts` | перелік команд і збережені shortcuts |
| POST | `/api/commands/exec`, `/api/commands/shortcuts`, `/api/commands/shortcuts-reorder` | запустити команду, зберегти shortcut, переставити |
| GET | `/api/nvs/list`, `/api/nvs/blob?key=…` | записи NVS, сирий блоб у hex |
| POST/DELETE | `/api/nvs/entry` | створити, змінити, видалити ключ |
| GET | `/api/fs/list?path=/` | вміст каталогу + зайнято/всього |
| GET | `/api/fs/raw?path=…` | файл цілком, потоком; `&download=1` — як вкладення |
| POST | `/api/fs/file`, `/api/fs/mkdir`, `/api/fs/rename` | запис, каталог, перейменування |
| DELETE | `/api/fs/remove?path=…` | видалити файл або порожній каталог |
| GET | `/api/screen/info`, `/api/screen/strip?fmt=332\|565` | геометрія екрана й одна смуга кадру сирими байтами |

Майже все, що змінює стан, відповідає `202 {"jobId":N}` — виконується воно в
`loop()`, а не в таску сервера, і результат забирається з `/api/job?id=N`.

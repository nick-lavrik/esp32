# Веб-портал пристрою

Портал — це одна сторінка `data/www/index.html` плюс розділи-модулі в
`lib/WebPortal/`. Працює на ESP32 з ~70-160 КБ вільного heap'а, часто через
власну точку доступу без інтернету. Майже всі правила нижче ростуть саме
звідси.

## Що де лежить

| Файл | Роль |
|---|---|
| `data/www/index.html` | вся сторінка: розмітка, CSS, JS в одному файлі |
| `lib/WebPortal/WebPortal.{hpp,cpp}` | транспорт, автентифікація, статика, `/api/status`, `/api/job` |
| `lib/WebPortal/IWebModule.hpp` | контракт розділу: `name()`, `registerRoutes()`, `loop()` |
| `lib/WebPortal/Web*Module.{hpp,cpp}` | розділи: wifi, console, commands, nvs |
| `lib/WebPortal/WebJobQueue.{hpp,cpp}` | черга дій, що виконуються в `loop()` |
| `lib/WebPortal/WebJson.hpp` | складання JSON вручну (`quote`/`ok`/`fail`/`error`) |
| `lib/WebPortal/WebPortalAssets.hpp` | ЗГЕНЕРОВАНА вшита копія сторінки — руками не правити |
| `tools/gen_web_assets.py` | генератор цього заголовка |

Розділи підключаються в `setupWebPortal()` у `src/main.cpp`.

## Цикл правки — повний, інакше змін не видно

```bash
# 1. правка data/www/index.html
./tools/gen_web_assets.py                      # 2. перегенерувати вшиту копію
pio run -e <env>                               # 3. зібрати
pio run -e <env> -t upload                     # 4. прошити
pio run -e <env> -t uploadfs                   # 5. ЗАЛИТИ LittleFS
```

Крок 5 пропустити не можна. Статика йде ланцюжком `CompositeStaticSource`:
LittleFS `/www` (пріоритет 100) → вшита копія (−100). Якщо в LittleFS лежить
стара сторінка, браузер отримає саме її, і свіжа прошивка нічого не змінить.
`uploadfs` переписує розділ цілком з `data/`, тому нічого не губиться — все,
що має там бути, лежить у `data/`.

Крок 2 теж обов'язковий: `WebPortalAssets.hpp` комітиться разом із джерелом,
щоб збірка не залежала від Python.

**Перед `-t upload` перевірити, яка плата фізично підключена.** У проєкті дві
ESP32-C6 з різним флешем, обидві на `/dev/ttyACM0`; чужий env дає boot-loop.
Env видно в топіку MQTT у лозі (`.../devices/<env>/status`) або в банері старту.

## Що виконується де

Обробник `AsyncWebServer` крутиться у власному таску AsyncTCP. У ньому **не
можна**: писати у flash (NVS, LittleFS), чіпати `WiFi.*`, блокувати надовго.
Усе таке кладеться в `WebJobQueue` і виконується в `loop()`.

```cpp
const uint32_t jobId = portal.jobs().submit([this, key]() { return _saveJob(key); });
if (jobId == 0) {
  request->send(503, "application/json", webjson::error("Job queue is full, try again"));
  return;
}
request->send(202, "application/json", String("{\"jobId\":") + jobId + "}");
```

Сторінка забирає результат опитуванням `/api/job?id=N` — це робить хелпер
`job()` у JS, окремо його писати не треба.

Через чергу йде і **читання**, якщо воно чіпає flash: `GET /api/nvs/list`
відповідає номером задачі, а не даними. Знімок у пам'яті (як
`_shortcutsJson` у `WebCommandsModule`) годиться лише тоді, коли дані міняє
лише сам модуль; те, що пишуть десятки місць прошивки, застаріє мовчки.

Черга — 4 слоти задач і 4 слоти результатів, фіксовано. Результат, який
витіснили, повертається як `expired`.

## Роути

- Шлях завжди з власним суфіксом: `/api/nvs/list`, а не `/api/nvs`.
  `AsyncCallbackWebHandler::canHandle()` вважає свій uri префіксом, тому
  `/api/nvs` перехопить і `/api/nvs/entry`. Ловилось на залізі: GET shortcuts
  віддавав список команд, мовчки — обидві відповіді валідний JSON.
- Формат помилки один на весь портал: `webjson::error("...")` → `{"error":"..."}`.
- Формат результату задачі один: `webjson::ok()` / `webjson::fail()` →
  `{"ok":bool,"message":"..."}`. Саме його розбирає `runAction()` у JS.
- Валідація параметрів — у роуті (швидка відмова 400), логіка — в job'і.
- Не вірити, що запис удався: `set*` у `ConfigStorage` нічого не повертають,
  а NVS буває заповнений. Перевіряти результат і віддавати `fail`.

## JSON

Відповіді складаються вручну через `webjson::quote()`, а не ArduinoJson:
документ там матеріалізується в heap цілком, а відповіді порталу — короткі
об'єкти, які й так треба перетворити на `String` для `request->send()`.
Для **розбору тіла** запиту — навпаки, ArduinoJson.

`quote()` екранує обов'язково: в SSID бувають лапки, у рядку логу — будь-що.

## Сторінка

- **Один файл, нуль зовнішніх залежностей.** Ні CDN, ні шрифтів, ні фреймворків:
  пристрій часто роздає власну точку доступу без інтернету, і зовнішній
  `<script src>` перетворив би портал на білий екран рівно тоді, коли він
  потрібен. Збірки теж немає — що написано, те й летить у flash.
- **Розмір під контролем.** Сторінка вшивається в прошивку gzip'ом; генератор
  друкує обидва числа. Орієнтир: ~48 КБ джерела → ~15 КБ у флеші.
- **Вивід англійською**, коментарі в коді — українською (див. CLAUDE.md).
  Це стосується і рядків UI, і `placeholder`, і текстів помилок.
- **Ховати через `el.hidden`.** У CSS сторінки є `[hidden] { display: none !important }`
  — і воно там не про охайність: атрибут `hidden` спирається на `display:none`
  з UA-стилю, тож будь-який авторський `display` його перемагає. На `.menu`
  з `display:flex` це дало приховані меню всіх рядків одночасно.
- **`escapeHtml()` на кожній вставці** даних у `innerHTML`. SSID, ключі NVS,
  значення — усе це прийшло ззовні.
- **Опитування тільки через `poller(fn, ms, isActive?)`.** Він не накладає
  запити один на одний, робить відступ при збоях і мовчить, поки вкладка
  невидима (`document.hidden`). `setInterval` накопичував десятки паралельних
  `fetch` — плата не встигала відповідати.
  *Наслідок для перевірки: у фоновому вікні браузера лічильники в шапці
  порожні — це не баг, а саме ця поведінка.*
- Готові хелпери, які треба використовувати, а не переписувати: `$()`,
  `api(path, opts)`, `form({...})`, `job(path, opts)`, `toast(text, kind)`,
  `runAction(path, opts)`, `escapeHtml()`, `poller()`, `signal(rssi, quality)`,
  `hhmmss(ms)`.
- **Секрети.** Портал відкритий будь-кому, хто вже в мережі пристрою (пароль у
  `ConfigStorage`, і поки він не заданий — авторизації немає). У списках, які
  показує сам портал, пароля бути не повинно: `WebWifiModule` віддає
  `hasPassword`, а не `password`.
  Розділ NVS — виняток і вважається привілейованим цілком: він показує сховище
  як є, а там і `nm_conn` (JSON профілів WiFi разом із паролями), і
  `nvs.net80211/ap.passwd`. Засліплювати окремі ключі там марно — сусідній
  рядок тієї ж таблиці покаже те саме. Захист тут один: `web auth <user> <pass>`.

### Розкладка

- Дві колонки: `<div class="cols"><div class="col">…</div><div class="col">…</div></div>`.
  `.col` має `min-width: 0` — без нього flex-елемент не стискається нижче
  ширини вмісту, і довгий рядок у таблиці розпирає колонку.
- `@media (max-width: 900px)` повертає одну колонку.
- Ділити треба те, що читають **паралельно** (список профілів поруч зі сканом),
  а не вміст вкладки навпіл.
- Вкладка Console — єдина на висоту вікна (`height: calc(100vh - 128px)`,
  стрічка `flex: 1`), щоб поле вводу було видно без скролу.
- Клас `.opt` ховає стовпчик на вузькому екрані.
- **Колонка-редактор поруч із довгим списком — `position: sticky; top: 16px`**
  (`#tab-nvs .col + .col`), і обов'язково `static` у `@media (max-width: 900px)`:
  в одноколонковій розкладці форма стоїть ПІД таблицею, і липнути їй нема до
  чого. Працює це тому, що `.cols` має `align-items: flex-start` — розтягнутий
  на висоту сусіда flex-елемент не липне.

### Дії в рядку таблиці

- **Клікабельний увесь рядок**, якщо в розділу є «головна» дія (View у NVS,
  вставка команди в Commands): `data-*` вішається і на `<tr>`, і на кнопку,
  обробник лишається один. Підсвітка — `tbody tr[data-...]:hover > td`
  (`> td`, а не `tr:hover`: фон рядка перекриється фоном комірок).
  Рядки-заглушки («Loading…», «Nothing matches.») атрибута не мають — тому
  самі собою не підсвічуються й не клікаються.
- **Тоді порядок перевірок в обробнику стає значущим.** `closest()` від
  кнопки Delete знаходить `<tr>`-предок із атрибутом головної дії, тож
  рідкісні дії перевіряються ПЕРШИМИ, а головна — останньою. Інакше Delete
  мовчки відкриває переглядач.
- Рідкісні дії — під стрілкою `▾` (`.menu-wrap`), головна лишається кнопкою.

## Перевірка

Збірка — не перевірка. Порядок:

```bash
# синтаксис JS без залізяки
python3 -c "import re;s=open('data/www/index.html').read();\
open('/tmp/p.js','w').write(re.search(r'<script>(.*)</script>',s,re.S).group(1))" && node --check /tmp/p.js

# API на живій платі (IP: ./esp net)
J=$(curl -s http://<ip>/api/nvs/list); ID=$(echo "$J"|sed 's/[^0-9]//g')
sleep 1; curl -s "http://<ip>/api/job?id=$ID"
```

Далі — очима, через браузерні інструменти: розкладку й типографіку інакше не
перевірити, і саме там видно те, чого не видно в JSON (капс у назві
namespace, поле, що наїжджає на сусіднє).

Серіал: `./esp <команда>` — не чіпає DTR/RTS, тому плата не ресетиться.

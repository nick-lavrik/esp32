# Веб-портал пристрою

Портал — це одна сторінка `assets/www/index.html` плюс розділи-модулі в
`lib/WebPortal/`. Працює на ESP32 з ~70-160 КБ вільного heap'а, часто через
власну точку доступу без інтернету. Майже всі правила нижче ростуть саме
звідси.

## Що де лежить

| Файл | Роль |
|---|---|
| `assets/www/index.html` | вся сторінка: розмітка, CSS, JS в одному файлі |
| `data/www/.readme.md` | те саме, але для того, хто відкрив Files на пристрої |
| `lib/WebPortal/WebPortal.{hpp,cpp}` | транспорт, автентифікація, статика, `/api/status`, `/api/job` |
| `lib/WebPortal/IWebModule.hpp` | контракт розділу: `name()`, `registerRoutes()`, `loop()` |
| `lib/WebPortal/Web*Module.{hpp,cpp}` | розділи: wifi, console, commands, nvs, files |
| `lib/WebPortal/WebJobQueue.{hpp,cpp}` | черга дій, що виконуються в `loop()` |
| `lib/WebPortal/WebJson.hpp` | складання JSON вручну (`quote`/`ok`/`fail`/`error`) |
| `lib/WebPortal/WebPortalAssets.hpp` | ЗГЕНЕРОВАНА вшита копія сторінки — руками не правити |
| `tools/gen_web_assets.py` | генератор цього заголовка |
| `tools/pio_web_assets.py` | pre-script PlatformIO: кличе генератор перед кожною збіркою |

Розділи підключаються в `setupWebPortal()` у `src/main.cpp`.

## Цикл правки

```bash
# 1. правка assets/www/index.html
pio run -e <env> -t upload                     # 2. прошити (вшиту копію
                                               #    перегенерує pre-script)
```

**`uploadfs` тут більше не потрібен** — і це головне, що змінилось 15.09.2026.
Сторінка живе в `assets/www/`, тобто ПОЗА образом LittleFS, і їде всередині
прошивки. Раніше вона лежала в `data/www/`, і забутий `uploadfs` означав, що
браузер мовчки отримує стару сторінку: LittleFS `/www` має вищий пріоритет за
вшиту копію.

**Руками генератор запускати більше не треба.** `extra_scripts =
pre:tools/pio_web_assets.py` у `[env]` викликає `tools/gen_web_assets.py` перед
кожною збіркою; заголовок перезаписується лише при реальній зміні вмісту, тому
зайвої перекомпіляції немає (gzip там із `mtime=0` — інакше той самий вхід
давав би щоразу інший байт). Раніше цей крок був ручним, і забутий він означав
прошивку зі старою сторінкою — мовчки, бо збірка проходила успішно.

`WebPortalAssets.hpp` усе одно **комітиться разом із джерелом**: так збірка не
залежить від наявності Python, а в дифі видно, що сторінка справді змінилась.

`uploadfs` лишається потрібним для вмісту LittleFS: фонові JPEG, профілі в
`/network/*.nmconnection`, `data/www/.readme.md`. Він переписує розділ **цілком
з `data/`**, тому все, що залито через вкладку Files і не лежить у `data/`,
після нього зникне.

**Кастомна статика — через LittleFS `/www`.** Файл, покладений туди за тим
самим шляхом, перекриває вшиту сторінку (пріоритет 100 проти −100); видалення
файла повертає вшиту. Класти можна прямо з порталу — вкладка Files → `/www` →
New file, без кабелю. Описано це і для того, хто дивиться з пристрою, —
`data/www/.readme.md`; **при зміні маршрутів оновлювати і його**.

**Перед `-t upload` перевірити, яка плата фізично підключена.** У проєкті дві
ESP32-C6 з різним флешем, обидві на `/dev/ttyACM0`; чужий env дає boot-loop.
Env видно в топіку MQTT у лозі (`.../devices/<env>/status`) або в банері старту.

## Що виконується де

Обробник `AsyncWebServer` крутиться у власному таску AsyncTCP. У ньому **не
можна**: писати у flash (NVS, LittleFS), чіпати `WiFi.*`, блокувати надовго.
Усе таке кладеться в `WebJobQueue` і виконується в `loop()`.

```cpp
const uint32_t jobId = portal.jobs().submit([this, key]() { return _saveJob(key); });
if (jobId == 0) {
  request->send(503, "application/json", webjson::error("Job queue is full, try again"));
  return;
}
request->send(202, "application/json", String("{\"jobId\":") + jobId + "}");
```

Сторінка забирає результат опитуванням `/api/job?id=N` — це робить хелпер
`job()` у JS, окремо його писати не треба.

Через чергу йде і **читання**, якщо воно чіпає flash: `GET /api/nvs/list`
відповідає номером задачі, а не даними. Знімок у пам'яті (як
`_shortcutsJson` у `WebCommandsModule`) годиться лише тоді, коли дані міняє
лише сам модуль; те, що пишуть десятки місць прошивки, застаріє мовчки.

Черга — 4 слоти задач і 4 слоти результатів, фіксовано. Результат, який
витіснили, повертається як `expired`.

## Роути

- Шлях завжди з власним суфіксом: `/api/nvs/list`, а не `/api/nvs`.
  `AsyncCallbackWebHandler::canHandle()` вважає свій uri префіксом, тому
  `/api/nvs` перехопить і `/api/nvs/entry`. Ловилось на залізі: GET shortcuts
  віддавав список команд, мовчки — обидві відповіді валідний JSON.
- Формат помилки один на весь портал: `webjson::error("...")` → `{"error":"..."}`.
- Формат результату задачі один: `webjson::ok()` / `webjson::fail()` →
  `{"ok":bool,"message":"..."}`. Саме його розбирає `runAction()` у JS.
- Валідація параметрів — у роуті (швидка відмова 400), логіка — в job'і.
- Не вірити, що запис удався: `set*` у `ConfigStorage` нічого не повертають,
  а NVS буває заповнений. Перевіряти результат і віддавати `fail`.

## JSON

Відповіді складаються вручну через `webjson::quote()`, а не ArduinoJson:
документ там матеріалізується в heap цілком, а відповіді порталу — короткі
об'єкти, які й так треба перетворити на `String` для `request->send()`.
Для **розбору тіла** запиту — навпаки, ArduinoJson.

`quote()` екранує обов'язково: в SSID бувають лапки, у рядку логу — будь-що.

## Сторінка

- **Один файл, нуль зовнішніх залежностей.** Ні CDN, ні шрифтів, ні фреймворків:
  пристрій часто роздає власну точку доступу без інтернету, і зовнішній
  `<script src>` перетворив би портал на білий екран рівно тоді, коли він
  потрібен. Збірки теж немає — що написано, те й летить у flash.
- **Розмір під контролем.** Сторінка вшивається в прошивку gzip'ом; генератор
  друкує обидва числа. Орієнтир: ~72 КБ джерела → ~22 КБ у флеші.
- **Рядок: 120 символів — м'яка межа, 180 — тверда.** До 120 добре (те саме
  число, що в `.clang-format` проєкту), понад 180 — не буває: розмітка з
  шаблонними рядками JS інколи не ріжеться красиво, і ламати її заради
  дотримання 120 гірше, ніж лишити довгий рядок. Рахується в СИМВОЛАХ, а не
  байтах: коментарі тут українські, і в UTF-8 кирилиця подвоюється, тому
  `awk 'length>120'` бреше — міряти python'ом (`len(line)`).

  Прогнати через prettier не можна: він переформатує файл цілком, а тут в
  одному файлі HTML, CSS і JS, у розмітці — шаблонні рядки JS, і перенос у
  невдалому місці міняє те, що бачить користувач. Тому переносити руками, і
  дивитись, куди саме падає перенос:

  - у тегу — між атрибутами (зайвий пробіл усередині тега нічого не значить);
  - у тексті `<p>`/`<h2>` — по пробілу між словами (HTML його згортає);
  - у шаблонному рядку JS (` `` `) — **не всередині текстового вмісту
    елемента**: там перенос стане справжнім пробілом у підписі кнопки;
  - у рядковому літералі JS — не переносити зовсім, краще розбити вираз.
- **Вивід англійською**, коментарі в коді — українською (див. CLAUDE.md).
  Це стосується і рядків UI, і `placeholder`, і текстів помилок.
- **Ховати через `el.hidden`.** У CSS сторінки є `[hidden] { display: none !important }`
  — і воно там не про охайність: атрибут `hidden` спирається на `display:none`
  з UA-стилю, тож будь-який авторський `display` його перемагає. На `.menu`
  з `display:flex` це дало приховані меню всіх рядків одночасно.
- **Кнопка, що міняє назву, не міняє розмір.** Підпис за станом («Pause» /
  «Resume», «Scan networks» / «Scanning…») мусить мати `min-width` під
  найдовший варіант — у `ch`, щоб не залежати від шрифту. Інакше сусідні
  елементи стрибають рівно тоді, коли користувач цілиться в кнопку, і замість
  «Resume» натискається те, що під'їхало на її місце. Помилка тиха: у
  статичному скриншоті її не видно, перевіряти треба в обох станах.
- **Будь-яка мутація, що чекає `job()`/`runAction()` перед перемальовкою, показує спінер.**
  Третій аргумент — `busyEl` (кнопка, що клікнута, чи `ev.submitter` для сабміту
  форми) — вмикає клас `.busy`: елемент ховається (`visibility`, не `display` —
  розмір лишається той самий), а `::after` малює кільце, що крутиться. Правило
  без винятків, бо мережа тут — власна точка доступу пристрою, і пауза між
  кліком і результатом легко читається як зависання. Виняток — контрол, що й
  так показує стан текстом (`#btn-scan`: «Scan networks» → «Scanning…», та сама
  домовленість, що в пункті вище про `min-width`): другий індикатор поверх
  першого був би зайвим.
  Читання, що не веде до мутації (список NVS/файлів при відкритті вкладки,
  перегляд блоба) спінера не потребує — там уже є свій текстовий стан
  («reading…») або дію ще не читають як «збереження».
- **Не `trim()`-ати те, що пристрій зберігає байт у байт.** Пробіл на краю
  значущий у SSID (`"Asus "` у `src/WifiNetworks.hpp` — справжнє ім'я мережі),
  у паролі й у рядковому значенні NVS. `value.trim()` у збиральнику форми
  коштував профілю: збережений SSID виглядав правильно, але мережі з таким
  іменем в ефірі немає, тож підключення не відбувалось ніколи, і помилки
  ніде не було. Trim доречний там, де пробіл справді зайвий — IP-адреси,
  фільтри, імена команд. Дзеркальне до цього: **показувати такий рядок
  видимо** — кожен пробіл на краю SSID сторінка малює міткою `.ws`:
  місце шириною в пробіл із намальованою крапкою по центру (`ssidLabel()`).
  Лапки для цього не годяться — вони читаються як частина імені.
- **`escapeHtml()` на кожній вставці** даних у `innerHTML`. SSID, ключі NVS,
  значення — усе це прийшло ззовні.
- **Великі дані читає браузер, а не пристрій.** Файл на 276 КБ віддається
  потоком (`/api/fs/raw`), і вкладка робить із ним усе сама: розпізнає текст,
  декодує UTF-8, малює `xxd`, показує картинку в `<img>`. Роут, що пакував
  початок файла в JSON, був і прибраний — у слоті `WebJobQueue` дані лежать у
  heap'і цілком, а стеля показу ще й потребує пояснення в UI. Правило: якщо
  браузер уміє це сам — хай робить сам, пристрій лише відкриває `File`.
- **Опитування тільки через `poller(fn, ms, isActive?)`.** Він не накладає
  запити один на одний, робить відступ при збоях і мовчить, поки вкладка
  невидима (`document.hidden`). `setInterval` накопичував десятки паралельних
  `fetch` — плата не встигала відповідати.
  *Наслідок для перевірки: у фоновому вікні браузера лічильники в шапці
  порожні — це не баг, а саме ця поведінка.*
- Готові хелпери, які треба використовувати, а не переписувати: `$()`,
  `api(path, opts)`, `form({...})`, `job(path, opts, busyEl?)`, `toast(text, kind)`,
  `runAction(path, opts, busyEl?)`, `setBusy(el, bool)`, `escapeHtml()`, `poller()`,
  `signal(rssi, quality)`, `hhmmss(ms)`.
- **Секрети.** Портал відкритий будь-кому, хто вже в мережі пристрою (пароль у
  `ConfigStorage`, і поки він не заданий — авторизації немає). У списках, які
  показує сам портал, пароля бути не повинно: `WebWifiModule` віддає
  `hasPassword`, а не `password`.
  Розділ NVS — виняток і вважається привілейованим цілком: він показує сховище
  як є, а там і `nm_conn` (JSON профілів WiFi разом із паролями), і
  `nvs.net80211/ap.passwd`. Засліплювати окремі ключі там марно — сусідній
  рядок тієї ж таблиці покаже те саме. Захист тут один: `web auth <user> <pass>`.

### Порядок вкладок

- **Вкладка Console — завжди остання** у `<nav>` (і серед `<section>` теж,
  для узгодженості). Це журнал і "аварійний" доступ до консолі, а не робочий
  розділ — місце для нового постійного розділу перед нею, не після.
- **Вкладка, чий розділ є не на кожній платі, за замовчуванням `hidden`** і
  з'являється сама, коли `/api/status` показує її ім'я в `modules` (Screen —
  `HAS_SCREEN_MIRROR`, EcoFlow — `HAS_ECOFLOW_CLIENT`). Назад не ховаємо
  ніколи: перелік `modules` не змінюється без переприв'язки прошивки, тому
  досить перевірити один раз, щойно він прийшов.

### Розкладка

- Дві колонки: `<div class="cols"><div class="col">…</div><div class="col">…</div></div>`.
  `.col` має `min-width: 0` — без нього flex-елемент не стискається нижче
  ширини вмісту, і довгий рядок у таблиці розпирає колонку.
- `@media (max-width: 900px)` повертає одну колонку.
- Ділити треба те, що читають **паралельно** (список профілів поруч зі сканом),
  а не вміст вкладки навпіл.
- Вкладка Console — єдина на висоту вікна (`height: calc(100vh - 128px)`,
  стрічка `flex: 1`), щоб поле вводу було видно без скролу.
- Клас `.opt` ховає стовпчик на вузькому екрані.
- **Колонка-редактор поруч із довгим списком — `position: sticky; top: 16px`**
  (`#tab-nvs .col + .col`), і обов'язково `static` у `@media (max-width: 900px)`:
  в одноколонковій розкладці форма стоїть ПІД таблицею, і липнути їй нема до
  чого. Працює це тому, що `.cols` має `align-items: flex-start` — розтягнутий
  на висоту сусіда flex-елемент не липне.
- **`sticky` мовчки не працює, якщо елемент ВИЩИЙ за екран.** Це не помилка в
  правилі — так воно й визначене: прилипати нема куди, коли елемент і так не
  вміщається. У Files на це наступили: редактор до 24 рядків + підказка +
  переглядач на 50vh разом переростають вікно, і колонка просто їхала вгору зі
  сторінкою, хоча `position: sticky` стояв. Лікує стеля висоти з власним
  скролом (`max-height: calc(100vh - 32px); overflow-y: auto`), яку теж треба
  зняти в одноколонковій розкладці.

### Дії в рядку таблиці

- **Клікабельний увесь рядок**, якщо в розділу є «головна» дія (View у NVS,
  вставка команди в Commands): `data-*` вішається і на `<tr>`, і на кнопку,
  обробник лишається один. Підсвітка — `tbody tr[data-...]:hover > td`
  (`> td`, а не `tr:hover`: фон рядка перекриється фоном комірок).
  Рядки-заглушки («Loading…», «Nothing matches.») атрибута не мають — тому
  самі собою не підсвічуються й не клікаються.
- **Якщо головна дія РІЗНА для різних рядків — селектор підсвітки має знати
  про всі.** У Files каталог несе `data-fs-open`, а файл `data-fs-view`, і в
  CSS спершу опинився лише перший: підсвічувались каталоги, файли — ні.
  Помилка тиха (нічого не ламається, просто зникає відгук), тому перевіряти
  треба наведенням на рядок кожного типу, а не на перший-ліпший.
- **Тоді порядок перевірок в обробнику стає значущим.** `closest()` від
  кнопки Delete знаходить `<tr>`-предок із атрибутом головної дії, тож
  рідкісні дії перевіряються ПЕРШИМИ, а головна — останньою. Інакше Delete
  мовчки відкриває переглядач.
- Рідкісні дії — під стрілкою `▾` (`.menu-wrap`), головна лишається кнопкою.
- **Стрілка `▾` — того ж кольору, що й кнопка, до якої вона пришита.** Пара
  `.chip` — це дві половини одного контрола, тож акцентна кнопка отримує
  акцентну стрілку, ghost-кнопка — ghost-стрілку. Приглушений гліф
  (`color: var(--muted)`) лишається тільки на ghost: на акцентному тлі це
  темно-сіре по блакитному, тобто найгірший контраст рівно там, куди
  цілиться курсор. Половини розділяє внутрішня лінія
  (`box-shadow: inset 1px 0 0`), бо рамки в акцентної кнопки немає.

## Перевірка

Збірка — не перевірка. Порядок:

```bash
# синтаксис JS без залізяки
python3 -c "import re;s=open('assets/www/index.html').read();\
open('/tmp/p.js','w').write(re.search(r'<script>(.*)</script>',s,re.S).group(1))" && node --check /tmp/p.js

# API на живій платі (IP: ./esp net)
J=$(curl -s http://<ip>/api/nvs/list); ID=$(echo "$J"|sed 's/[^0-9]//g')
sleep 1; curl -s "http://<ip>/api/job?id=$ID"
```

Далі — очима, через браузерні інструменти: розкладку й типографіку інакше не
перевірити, і саме там видно те, чого не видно в JSON (капс у назві
namespace, поле, що наїжджає на сусіднє).

Серіал: `./esp <команда>` — не чіпає DTR/RTS, тому плата не ресетиться.
